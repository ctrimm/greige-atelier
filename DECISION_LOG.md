# Decision Log

- 2026-10-24 — Design language: full-bleed warm greige ground, warm
  off-white high-contrast serif display type (one italic word per
  headline as the counterpoint), monospace for the studio's notes and
  manifesto, pale stone reserved for the footer panel. Large unframed
  photography, hairline rules, no cards/shadows/buttons except the
  pill CTA. All copy original to this project.
- 2026-10-24 — Stack: Astro ^7.4.2 static + SST ^3 (sst.aws.Astro,
  S3 + CloudFront), matching the owner's other SST v3 Astro sites.
  Deploy stays the owner's step (standing rule).
- 2026-10-24 — Studio persona: fully fictional — Maren Vale Interiors,
  interior design studio (Charleston · Copenhagen, est. 2016), with
  five original projects (Stonehouse Kitchen, Hearth Room, Arch Bedroom,
  Marble Bath, Long Table Room) and a fictional commission list.
- 2026-10-24 — Images: all 6 site photographs are AI-generated for this
  project — one hero interior, one atelier detail, and four project
  rooms sliced from a single 2×2 sheet for a consistent palette
  (originals in source-images/). Responsive variants are generated by
  scripts/optimize-images.py; imgSrcset() includes only variants that
  exist on disk, so a swapped photo degrades gracefully.
- 2026-10-24 — Palette contrast (measured): on the greige ground
  #66584b, body ink #f7f2e9 = 6.15:1 and the pale-brass accent #f0dcae
  = 5.08:1 — the accent is used for small labels/numerals, so it had to
  pass AA for normal text, not just large text. The ground was deepened
  from #776b5e (accent candidates failed at 2.8–4.2:1) to make that
  possible. The unit suite recomputes these ratios from the shipped
  config on every run.
- 2026-10-24 — Config: all owner-editable content/theme lives in
  `site.config.ts` (repo root), heavily commented for non-technical
  owners; `src/data/site.ts` is plumbing only — validateConfig() fails
  the build with a plain-language problem list, and pure helpers
  (slugify, headlineParts, themeCssVars, projectRoutes, imgSrcset,
  url) are unit-tested.
- 2026-10-24 — Base path: astro.config reads SITE/BASE from env — root
  for local/SST, /greige-atelier subpath for Pages. Every internal URL
  goes through url() (nav, images, srcsets, fonts, favicon, sitemap,
  llms.txt); an integration suite builds in subpath mode and asserts
  the prefixes. That suite must spawn its build with a clean env
  (PATH/HOME/SITE/BASE only) — an inherited variable once made Vite
  silently drop site/base.
- 2026-10-24 — Reveal animation: rise-only (transform); hidden state is
  visibility:hidden; NO opacity fade — axe/Lighthouse snapshot mid-fade
  and report phantom contrast failures on half-blended colors.
- 2026-10-24 — AI readiness: generated /llms.txt (from config),
  schema.org LocalBusiness JSON-LD on every page, generated
  /sitemap.xml, robots.txt explicitly welcoming AI crawlers.
- 2026-10-24 — CI/CD (modeled on the owner's other Astro theme repos):
  ci.yml runs unit+integration, Playwright e2e, and Lighthouse on every
  push/PR; deploy.yml runs the full suite, then builds with SITE/BASE
  and deploys to GitHub Pages. Node pinned to 22.23.4 — Astro 7.4.2
  hard-fails below it. SITE/BASE are scoped to the deploy build job
  only: at workflow level they leak into the test job, where the e2e
  preview serves under the subpath and Playwright's root-URL check
  times out (learned on the previous template; applied here from the
  start).
- 2026-10-24 — Lighthouse stance: Accessibility/Best Practices/SEO are
  hard 100 gates locally and in CI (verified 100 on all six graded
  routes). Performance is report-only in CI — the score is dominated by
  the grading machine's CPU and simulated network (88–99 locally in the
  sandbox); locally `npm run grade` keeps the strict bar visible.
- 2026-10-24 — Tests: 165 total (94 unit, 46 integration, 25 Playwright
  e2e), all green locally before first push.
